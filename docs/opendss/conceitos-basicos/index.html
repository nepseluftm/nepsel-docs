Conceitos Básicos do OpenDSS

O Open Distribution System Simulator (OpenDSS) utiliza uma linguagem própria baseada em comandos textuais para representar os componentes de um sistema elétrico de distribuição.

Cada elemento da rede é criado por meio de uma classe específica, como circuito, linha, transformador, carga, gerador, sistema fotovoltaico ou banco de baterias. Os parâmetros elétricos e operacionais desses elementos podem ser definidos diretamente nos comandos ou organizados em arquivos com extensão .dss.

A compreensão dos conceitos básicos da ferramenta é fundamental para construir modelos coerentes, interpretar corretamente os resultados e evitar erros relacionados às unidades, conexões, níveis de tensão e sequência de execução dos comandos.

Estrutura Geral de um Comando​

A criação de um elemento normalmente utiliza a instrução New, seguida da classe do componente, de seu nome e dos respectivos parâmetros.

New Classe.Nome Parametro1=Valor1 Parametro2=Valor2

Exemplo:

New Load.Carga01 Bus1=barra1.1.2.3 Phases=3 Conn=wye kV=0.22 kW=15 PF=0.92

Nesse comando:

  • New cria um novo elemento;
  • Load identifica a classe do elemento;
  • Carga01 corresponde ao nome atribuído à carga;
  • Bus1 define a barra de conexão;
  • Phases informa o número de fases;
  • Conn define o tipo de ligação;
  • kV informa a tensão nominal;
  • kW define a potência ativa;
  • PF representa o fator de potência.

Os parâmetros podem ser escritos em uma única linha ou distribuídos em várias linhas com o caractere ~.

New Load.Carga01
~ Bus1=barra1.1.2.3
~ Phases=3
~ Conn=wye
~ kV=0.22
~ kW=15
~ PF=0.92

Limpeza do Ambiente​

Antes de iniciar uma nova simulação, recomenda-se utilizar:

Clear

Esse comando remove os elementos anteriormente carregados e evita que componentes de outra simulação permaneçam na memória.

Barras Elétricas​

As barras representam os pontos de conexão elétrica do circuito e são criadas automaticamente quando aparecem nos parâmetros dos elementos.

Bus1=barra1
Bus2=barra2

A indicação dos nós é feita após o nome da barra:

Bus1=barra1.1.2.3
  • .1: fase A;
  • .2: fase B;
  • .3: fase C;
  • .0: neutro ou referência.

Exemplo fase-neutro:

Bus1=barra1.1.0

Exemplo entre duas fases:

Bus1=barra1.1.2

Número de Fases e Condutores​

  • Phases: número de fases elétricas;
  • NConds: número de condutores representados.
Phases=3
NConds=3

Com neutro explícito:

Phases=3
NConds=4

Tipos de Ligação​

Estrela​

Conn=wye

ou:

Conn=star

Triângulo​

Conn=delta

A escolha incorreta da ligação altera tensões, correntes e potências calculadas.

Unidades de Tensão​

As tensões são normalmente informadas em quilovolts:

kV=13.8
kV=0.38
kV=0.22

Para um sistema trifásico equilibrado em estrela:

VL = √3 × VF

VF = VL / √3

Bases de Tensão​

Set VoltageBases=[13.8, 0.38, 0.22]
CalcVoltageBases

Set VoltageBases informa os níveis existentes, enquanto CalcVoltageBases associa as barras às bases mais próximas.

Erros Frequentes​

  • tensão informada em volts quando o parâmetro espera quilovolts;
  • barra escrita com nome diferente;
  • número incorreto de fases;
  • ligação estrela ou triângulo incorreta;
  • sequência errada de nós;
  • ausência do comando Clear;
  • arquivo chamado por Redirect inexistente;
  • caminho com espaços sem aspas;
  • bases de tensão não definidas;
  • potência nominal incompatível;
  • duplicação do nome de elementos;
  • ausência de conexão elétrica entre partes da rede;
  • unidades de comprimento incompatíveis com as impedâncias;
  • parâmetros de transformadores associados ao enrolamento incorreto.

Sequência Recomendada de Modelagem​

  1. limpar o ambiente;
  2. criar o circuito principal;
  3. definir os modelos de condutores;
  4. criar as linhas;
  5. inserir os transformadores;
  6. inserir as cargas;
  7. incluir a geração distribuída;
  8. incluir os sistemas de armazenamento;
  9. adicionar os controles;
  10. incluir monitores e medidores;
  11. definir as bases de tensão;
  12. configurar o modo de solução;
  13. executar a simulação;
  14. verificar a convergência;
  15. analisar os resultados;
  16. comparar os resultados com os valores esperados.

Boas Práticas​

  • utilizar nomes claros;
  • separar o projeto em arquivos;
  • documentar as fontes dos dados;
  • manter as unidades consistentes;
  • utilizar um arquivo principal;
  • criar os modelos progressivamente;
  • testar cada novo elemento;
  • verificar a conectividade;
  • conferir o balanço de potência;
  • comparar os resultados com cálculos manuais;
  • manter cópias das versões anteriores;
  • utilizar controle de versão;
  • registrar hipóteses;
  • registrar a versão do OpenDSS utilizada;
  • preservar os arquivos de entrada utilizados nos estudos.

Considerações Técnicas​

A linguagem do OpenDSS é baseada na criação de objetos elétricos por meio de comandos textuais.

A qualidade dos resultados depende da correta definição das barras, nós, níveis de tensão, ligações, parâmetros elétricos, cargas, fontes, curvas temporais, modos de solução, unidades e sequência de execução dos arquivos.

O aprendizado inicial deve priorizar a construção de circuitos simples e a verificação dos resultados antes da inclusão de equipamentos e controles mais complexos.

A organização modular dos arquivos, a documentação dos parâmetros e a validação progressiva são fundamentais para garantir a rastreabilidade e a confiabilidade dos estudos desenvolvidos no OpenDSS.
